# Balcony weather station

## v2.0.4 — BME280 측정 전압 실험

- Wi-Fi를 켜지 않고 기존 BME280 강제 측정·읽기 경로만 반복하는 `bme_measure` 단계를 추가합니다.
- 표본에 대기(0), 측정 명령·변환 대기(1), I²C 읽기·보정(2)을 표시합니다. 정규 ADC·관측 큐·서버 측정 데이터와 섞지 않습니다.
- 4번 예제는 20ms 간격으로 대기 2초, 반복 측정 7초, 회복 2초를 기록합니다. 센서 초기화와 20ms보다 짧은 순간 변화는 이 시험 범위가 아닙니다.

- 각 실험 상세 화면에서 마지막 확인 전압, 연결 대기·전체 시도 시간, HTTP 시도·확인 표본 수를 보여줍니다. 2.0.2 이하 결과에는 소급되지 않습니다.

| 항목 | 설정 |
| --- | --- |
| 보드 | DFRobot FireBeetle 2 ESP32-C6, DFR1075 V1.2, 4 MB |
| 프레임워크 | PlatformIO espressif32 6.12.0 / ESP-IDF 5.5.0 |
| BME280 | 3.3 V / GND / SDA GPIO19 / SCL GPIO20; 0x76 또는 0x77 |
| 배터리 | 보호회로가 있는 단셀 INR18650-35E; 커넥터 극성 확인 |
| 전압 측정 | 보드 내장 ADC0 분압 ×2, 보정 ADC 16회 평균 |
| 관측 | JST 매시 00·15·30·45분 부근, 사이에는 deep sleep |
| 장치 식별 | `home-lab / balcony-01 / balcony-weather-01` |
| 원시 값 | `air_temperature` °C, `humidity` %, `pressure` hPa, `battery_voltage` V |

고정 PlatformIO 플랫폼의 C6 지원을 위해 ESP-IDF를 사용합니다. 타워용 Arduino
프로젝트를 교체한 것이 아닙니다. Bosch BME280 SensorAPI는 v3.5.1 고정 커밋입니다.
배터리 잔량은 브라우저에서만 전압 기반으로 추정합니다. 환산표 버전은
`samsung-35e-2014-0p2c-v1`이며, 삼성 INR18650-35E의 2014년 11월
잠정 사양서 3쪽 상온·0.2C(680mA) 방전곡선을 근사합니다.
잔량은 `100 × (1 - 방전된 용량 / 3482mAh)`로 환산한 점 사이를 선형 보간합니다.
0%는 2.65V, 완충 기준점은 4.2V입니다. 예: 3.3V 약 14%, 3.8V 약 67%.
이는 휴지전압 기반 SOC나 장치 실측 보정값이 아니며 온도·충전·부하의 영향을 받습니다.
3.3V 운용 하한/비상모드와는 별개이며, 이번 표시 변경은 펌웨어 제어에 영향을 주지 않습니다.
D1에는 전압만 저장하고 과거 그래프의 잔량도 같은 새 환산표로 다시 계산합니다.

태양광 패널 전압·전류 측정은 추가하지 않습니다. 실제 햇빛 아래 개방전압과 보드
입력 허용범위, 배터리 극성·충전 온도를 확인한 후 연결하세요. 실내 조명 아래
2.8 V만으로 충전 적합성을 판단하지 않습니다.

## 측정·복구 정책

- BME280 forced mode로 측정 후 센서는 sleep으로 돌아갑니다. 센서 실패는 `null`로
  남기며 배터리 등 다른 값은 전송합니다.
- 최초 전원 투입 후 NTP 동기화가 필요합니다. 첫 관측은 동기화 직후, 이후에는
  적용된 관측 주기의 경계로 맞춥니다. 절전 RTC 오차·부팅 시간 때문에 초 단위 오차는 있습니다.
- 날짜를 모르면 가짜 타임스탬프를 만들지 않습니다. 기존 큐는 유지합니다.
  v2.0.0은 하루마다, v2.0.1은 기상 중 이미 연결된 상태에서 약 한 시간마다 NTP를 시도합니다.
  실패해도 마지막 동기화 후 30일까지 RTC로 관측합니다.
  장기간 동기화가 없으면 오차가 누적됩니다. 전원 완전 상실 시 NTP가 다시 필요합니다.
- NVS 512 KiB 파티션에 **미전송 큐 최대 1,344건**을 보관합니다. 평상시 약 14일이며,
  전송 완료 데이터를 보관하는 아카이브가 아닙니다. 추가 재부팅/관측이 많으면
  보관 일수가 줄어듭니다. 가득 차면 가장 오래된 미전송 건을 제외하고 `dropped`를
  누적합니다. 저장소 오류 시 자동 포맷하지 않습니다.
- 저장 중 전원 차단 시 진행 중인 한 건은 유실될 수 있습니다. 기존 큐 커서를
  새 레코드와 혼동하지 않도록 교체 순서를 분리합니다.
- 부팅별 `boot_id`, 부팅 내 증가 `sequence`, 고정 `reading_id`를 사용합니다.
  일치하는 `reading_id`의 `accepted`/`duplicate` 응답을 받아야 큐에서 제외합니다.
  과거부터 복구하므로 긴 장애 직후에는 최신 화면 반영이 늦을 수 있습니다.

| 작업 | 제한 |
| --- | --- |
| 정상 기상 상태 | 부팅부터 최대 45초 후 절전 |
| Wi-Fi | 기상당 최대 2회, 각 최대 8초 |

| 제어 조회 | 평소 측정 응답에 포함; 필요 시 상태 요청 1회 추가 |
| 유지보수 | 새 요청마다 최대 15분; 미수신 요청은 1시간 후 만료 |
| 유지보수 폴링 | 30초 간격, 실패 시 즉시 재시도하지 않음 |
| OTA | 3.8 V 이상, 한 번 최대 120초 |
| OTA 재시도 | 현재 대상 이미지 최대 3회; 첫 실패 뒤 1시간, 다음 실패 뒤 6시간 |

시도 횟수는 다운로드 **전에** NVS에 저장해 재부팅으로 초기화되지 않습니다.
동일 대상 재승인은 횟수를 초기화하지 않습니다. 다른 이미지로 대상을 바꾸면 새
시도 예산을 사용합니다. 실행 중 버전보다 높은 `major.minor.patch`만 자동 설치합니다.

## 빌드만 하기

Windows ESP-IDF는 공백 포함 프로젝트 경로를 거부합니다. 아래 스크립트는
`%LOCALAPPDATA%/HydroponicsBuild/weather-station`에 소스를 복사하여 빌드합니다.
업로드하지 않으며 산출물은 `.pio/artifacts/<환경>/`에 복사합니다.

```powershell
# 저장소 루트: 자격 증명 없이 모든 Wi-Fi/TLS/OTA 코드 컴파일
.\weather-station\scripts\build.ps1 -Environment firebeetle_c6_compilecheck
# 실제 설정을 준비한 뒤 운영용 빌드만 실행
.\weather-station\scripts\build.ps1
```

`compilecheck` 환경은 고의로 무효인 서버·토큰·공개키를 사용하므로 **업로드 금지**입니다.
서명 도구도 이 이미지를 거부합니다. 일반 빌드 역시 `include/secrets.h`가 없으면
통신·OTA 비활성 예제 설정으로 컴파일되므로 실제 운용에 업로드하면 안 됩니다.
빌드 복사본에 `secrets.h`가 남을 수 있으므로 이 로컬 폴더도 공개 공유하지 마세요.

Wi-Fi SSID/비밀번호는 타워와 동일하게 사용할 수 있습니다. 로컬 기상대 설정에는
타워의 Wi-Fi 정보를 복사했으며, 이후 타워 설정 변경이 자동 동기화되지는 않습니다.
타워 ArduinoOTA 비밀번호는 기상대에서 사용하지 않습니다. 기상대는 관리자 승인과
서명 공개키로 OTA를 검증하므로 따로 입력할 OTA 비밀번호가 없습니다.
서버가 두 장치를 구별해야 하므로 장치 Bearer 토큰은 반드시 각각 발급합니다.

## 활성화 순서 — 서버 1~8 준비 완료, 장치 9~10 대기

1. 기존 D1 복구 지점 확보 후 `0012_weather_station_ota.sql`과
   `0013_station_audit.sql`을 적용합니다. 기존 테이블을 삭제/변경하지 않습니다.
2. `cloudflare-worker/scripts/enroll-weather-station.sql`을 검토 후 실행합니다.
   zone/device/4개 sensor/control을 등록하며 OTA 대상은 비워 둡니다.
3. 타워와 **별도** 장치 토큰을 발급합니다. `create-device-credential.mjs`는
   토큰과 SHA-256을 로컬에 출력하므로 채팅/공개 로그에 공유하지 마세요.
   토큰은 기상대 `secrets.h`에, 해시는 `device_credentials`에 저장합니다.
   `device_id=balcony-weather-01`, 별도 credential ID/label을 사용합니다.
   기존 `provision-device-credential.ps1`은 타워 전용이므로 그대로 쓰지 않습니다.
4. 아래 도구로 RSA-2048 서명키를 생성합니다. 개인키는 Git·Dropbox·Worker·R2·
   장치에 넣지 않고 비공개 로컬 폴더와 안전한 별도 백업에만 보관합니다.
5. 비공개 R2 버킷을 생성하고 `wrangler.jsonc`의 기존 `r2_buckets` 배열에
   `{"binding":"STATION_FIRMWARE","bucket_name":"<생성한 버킷>"}`를 추가합니다.
   기존 사진 버킷 설정은 유지하고 R2 public access는 끕니다.
6. Worker의 `STATION_OTA_PUBLIC_KEY`에 **공개키 PEM**을 설정합니다.
   장치에도 동일 공개키를 넣습니다. 서명 개인키가 아닙니다.
7. Cloudflare Access가 `/admin/*` 전체를 보호하는지 확인합니다. `/v1/station/*`은
   Access 로그인 대신 장치 Bearer 인증을 사용해야 합니다. 관리자 API도 Access
   JWT와 변경 요청의 동일 출처를 서버에서 검증합니다.
8. Worker/정적 파일 배포 후 `/weather/`, `/admin/station/`을 확인합니다.
   새 기상대용 cron은 없습니다. 타워 cron·조명·경보는 변경하지 않습니다.
9. `secrets.example.h`를 `secrets.h`로 복사해 Wi-Fi·토큰·서버·공개키를 넣고
   **일반 환경**으로 빌드합니다. 첫 USB 설치는 보드·포트를 확인한 뒤 부트로더/
   파티션/앱을 함께 설치합니다. 기존 타워 포트에 올리면 안 됩니다.
10. 아래 체크리스트와 실제 OTA/롤백을 검증한 뒤 밀폐 커버를 닫습니다.

키 생성 예시(먼저 만든 비공개 로컬 폴더로 경로 변경):

```powershell
node weather-station/scripts/release.mjs keygen C:/PrivateKeys/weather-ota.pem
node weather-station/scripts/release.mjs public-header C:/PrivateKeys/weather-ota.pem.public.pem
```

두 번째 명령의 공개키 `#define`을 기상대 `secrets.h`에 넣습니다. 키 회전은 기존
신뢰키로 서명한 펌웨어에 새 공개키를 넣고 검증한 후 Worker의 공개키를 바꾸는
순서입니다. 개인키 분실/잘못된 초기 공개키는 USB 복구가 필요할 수 있습니다.

## 이후 자동 OTA 릴리스

`CMakeLists.txt`의 `PROJECT_VER`을 증가시키고 테스트·일반 빌드 후 앱 이미지만
서명합니다. 부트로더/전체 플래시 이미지는 안 됩니다. `releases` 폴더는 미리 만들며
동일 출력 JSON은 덮어쓰지 않습니다.

```powershell
node weather-station/scripts/release.mjs sign weather-station/.pio/artifacts/firebeetle_c6/firmware.bin 1.0.1 C:/PrivateKeys/weather-ota.pem weather-station/releases/1.0.1.json
```

보통은 `scripts/prepare-release.ps1`을 사용하세요. 운영 설정의 토큰/공개키와
서명키 일치 여부를 검사하고 빌드·서명·버전별 보관을 한 번에 처리합니다.
관리 화면에서 **manifest.json + firmware.bin** 선택 → 업로드·검증·등록 →
버전 선택 → OTA 승인 순서입니다. 서버가 실제 이미지의 SHA-256·보드·앱 이름·
버전을 검사합니다. 등록만으로는 배포되지 않습니다. 같은 버전의 다른 바이너리를
교체할 수 없으며 수정 시 새 버전을 사용합니다. R2 객체도 덮어쓰지 않습니다.

장치는 TLS 인증서·RSA 서명·하드웨어 ID·앱 이름/버전·크기·SHA-256·ESP 이미지
유효성을 검사하고 비활성 슬롯에 씁니다. 첫 부팅의 로컬 저장소 검증 실패 시
롤백하며 네트워크/센서 불통 자체는 롤백 사유가 아닙니다. 이것은 앱 OTA 검증이지
eFuse Secure Boot/Flash Encryption이 아닙니다. 물리적 접근으로부터 완전히 보호하지 않습니다.

## 화면·서버·사용량

- `/weather/`: 네 값, 전압 기반 참고 잔량, 관측 시각·갱신 지연; 표시 중 15분 갱신.
- `/admin/station/`: Access 로그인, 유지보수 요청/종료, 상태·큐·재시도 정보,
  manifest 등록/승인/중지. 상태 확인은 수동 새로고침.
- `POST /v1/readings` + `X-Station-Protocol: 1`: 기존 ACK에 `station_control` 추가.
  헤더가 없는 타워 요청은 응답 모양과 제어 조회 횟수가 바뀌지 않습니다.
- `POST /v1/station/status`: 인증된 기상대 상태 보고 + 명령 조회.
- `GET /v1/station/firmware/<sha256>`: 인증 장치에 할당된 이미지 하나만 다운로드.
- `/admin/api/stations[/<device_id>]`: 인증된 관리자 조회/변경.
- `POST /admin/api/stations/<device_id>/firmware`: 서명 manifest 헤더 + 제한된 앱 BIN 업로드·검증·등록.
- `GET /admin/api/stations/<device_id>/events`: 최근 관리 이력 50건; 정기 상태 보고는 이력을 추가하지 않음.

정상 운용은 약 96개 관측/일, 측정값 행 384개/일입니다. 인덱스·인증·상태 쓰기가
추가되므로 D1 청구 쓰기 행 총계와 같지는 않습니다. OTA 때만 R2를 읽습니다.
대시보드/유지보수/복구 트래픽은 별도지만 반복을 제한했습니다. 기존 SQL 전체
백업에 새 테이블이 포함되며 해당 테이블이 있는 스냅샷에서만 건수 검증에 추가합니다.
마이그레이션 전 백업도 유지됩니다. R2 펌웨어와 개인키는 별도 보존 대상입니다.
일일보고서·기상대 알림·비교 그래프는 이번 범위 밖입니다.

## 설치 전 검증

로컬 테스트: `cd cloudflare-worker; node --test` (Node 22.13+ 또는 24 권장).
SQLite/메모리 객체로 마이그레이션, 부분 누락, 중복 ACK, 노드 분리, 서명 변조,
인증, 승인/중지, 만료, 백업 호환성을 검사하며 원격 서비스에는 접속하지 않습니다.

- [ ] 실물 버전·배선 및 ADC0 전압을 멀티미터로 확인
- [ ] 첫 USB 부팅, 4개 필드, 다음 15분 경계 관측 확인
- [ ] Wi-Fi 차단 → 절전 → 재연결 시 원시 시각·중복 방지 확인
- [ ] BME280 분리 시 `null`, 배터리 데이터 유지 확인
- [ ] 유지보수 시작·연장·종료·15분 제한·정시 관측 확인
- [ ] 정상 OTA 성공, 잘못된 서명/해시/보드/구버전 거부 확인
- [ ] OTA 전원 차단·부팅 실패 롤백 및 재시도 예산 보존 확인
- [ ] 저전압 OTA 차단, 실제 절전 전류·충전 성능·야외 온도 확인

컴파일 성공은 하드웨어 검증을 대체하지 않습니다. 자동 OTA는 사용자 데이터
파티션을 포맷하지 않지만 초기 USB 파티션 변경/복구 전에는 항상 대상을 확인합니다.
